# SOP Library

Every recurring Mohr OS operation has an SOP. An SOP must state owner, trigger, inputs, steps, outputs, and failure modes. No SOP is allowed to be vague.

## Files

- `client-onboarding.md`
- `content-production.md`
- `ad-launch.md`
- `sales-call.md`
- `weekly-review.md`
- `delivery-sprint.md`
- `vault-ingest.md`
- `experiment-log.md`

## SOP template

```
# SOP: <Name>

Owner: <agent or human>
Trigger: <when this runs>
Cadence: <frequency if scheduled>
Inputs: <what is needed to start>
Outputs: <what lands by the end>
Failure modes: <how this can break and recovery>

## Steps
1. ...
2. ...
```
