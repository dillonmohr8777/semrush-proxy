# Delivery Sprints

Every client install is broken into 10 working day sprints with revenue tied outcomes.

## Sprint shape

- Length: 10 working days
- Day 0: planning
- Days 1 to 9: execution with daily standups
- Day 5: midpoint check
- Day 10 morning: demo prep
- Day 10 afternoon: client demo
- Day 10 late: retro and next sprint draft

## Standard sprint library

Each install tier has default sprint sequences.

### Tier 1 Offer and Pipeline Install

| Sprint | Theme | Revenue outcome |
|---|---|---|
| 1 | ICP definition and offer canvas | Offer and ICP signed off |
| 2 | Cold sequence build and list install | First 200 prospects contacted |
| 3 | Reply optimization and first booked meetings | 5 qualified meetings |
| 4 | Sales enablement and proposal install | First proposals sent |

### Tier 2 Paid Media and CRO Install

| Sprint | Theme | Revenue outcome |
|---|---|---|
| 1 | Account audit and tracking fix | Attribution trusted |
| 2 | Creative system and first campaigns | First campaigns live |
| 3 | Landing page and CRO audit | Conversion rate lifted |
| 4 | Scale winners and kill losers | Payback on target |

### Tier 3 Full Revenue OS

Tiers 1 and 2 combined, plus:

| Sprint | Theme | Revenue outcome |
|---|---|---|
| 5 | Content engine install | First batch shipped and distributed |
| 6 | Sales system install | Pipeline dashboard live |
| 7 | Memory engine install | Vault live, ingest cadence running |
| 8 | Automation lab first 3 automations | Manual work cut by 40% |

## Rules

- Every sprint has exactly one revenue outcome
- No carryover tasks hidden across sprints. Carryover is called out in retro.
- Scope additions mid sprint require orchestrator approval
